# Tạo 1 dự án React Native mới và Deploy lên thiết bị di động
## 1. Cài đặt ExpoCLI (Nếu chưa cài đặt)
> Cài đặt ExpoCLI:
```bash
npm install -g expo-cli
```

## 2. Sử dụng ExpoCLI để tạo 1 dự án React Native mới
Ta sử dụng lệnh sau để tạo 1 dự án React Native mới:
- Đối với app `js` (Template Blank):
```bash
npx create-expo-app --template blank my-new-app
```
- Đối với app `typescript` (Template Blank):
```bash
npx create-expo-app --template blank-typescript my-new-app
```

## 4. Xây dựng `React Native` App mà không dùng `Expo`

### 4.1. Giới thiệu
Trước hết, để  xấy dựng `React Native` App mà không dùng `Expo`, ta cần lưu ý trên các thiết bị sau:
- `MacOS`: Có thể build được cả cho `IOS` và `Android`
- `Windows`: Chỉ có thể build được cho `Android`
- `Linux`: Chỉ có thể build được cho `Android`

Để có thể build được các app `React Native` mà không dùng `Expo`, ta cũng cần phải có các công cụ sau:
- `Android Studio`: Để build app cho `Android`. NÊN cài `SDK` và chọn `NDK Side by Side` và `CMake` khi cài đặt. (Khuyến khích cài tất cả các `SDK` trong `SDK Tools`)
- `XCode`: Để build app cho `IOS` (Chỉ trên `MacOS`)

Ngoài ra, còn cần phải cài đặt thêm các công cụ như `Node`, `JDK`, `Watcman`,... và set `environment` cho chúng, chi tiết tại: [Set Up React Native App](https://reactnative.dev/docs/set-up-your-environment)


### 4.2. So sánh `Expo (Managed Workflow)`, `Expo (Bare Workflow)`, `React Native (Bare Workflow)`
| `Expos (Managed Workflow)` | `Expos (Bare Workflow)` | `React Native (Bare Workflow)` |
|:------------------------:|:---------------------:|:---------------------------:|
| Dễ dàng thiết lập, xây dựng và làm việc | Tương đối dễ dàng thiết lập, xây dựng và làm việc | Các bước chuẩn bị, thiết lập có nhiều phức tạp hơn |
| Nhanh chóng, không mất quá nhiều thời gian trong quá trình `development` | Thuận tiện trong quá trình `development` | Thuận tiện trong quá trình `development` |
| Không có hoặc có rất ít việc phải viết thêm các `cấu hình` | Có thể viết thêm các `cấu hình` | Có thể bắt phải viết thêm nhiều các `cấu hình` cho project hơn |
| Có thể xấy dựng `cross-platform` (IOS, Android) hoặc `standalone` App | Có thể xây dựng `cross-platform` (IOS, Android) hoặc `standalone` App | `Standalone` App được xây dựng ở `local` |

> LƯU Ý: KHI KHÔNG DÙNG `EXPO` THÌ TẤT CẢ CÁC `QUYỀN` NHƯ `CAMERA`, `LOCATION`,... ĐỀU PHẢI ĐƯỢC `SETUP` BỞI CHÍNH CHÚNG TA. CỤ THỂ NHƯ SAU:
> - Đối với `Android`: Cần phải thêm một số `cấu hình` trong file `AndroidManifest.xml` và `build.gradle` tùy theo hướng dẫn của `Google`
> - Đối với `IOS`: Cần phải thêm một số `cấu hình` trong file `Info.plist` tùy theo hướng dẫn của `Apple`

### 4.3. Sử dụng `Expo (Bare Workflow)` để tạo 1 dự án `React Native` mới
Ta sử dụng lệnh sau để tạo 1 dự án `React Native` mới mà không dùng `Expo`:
```bash
npx react-native init <tên-dự-án>
```
Sau đó, ta chọn tuỳ chọn sau trong Terminal: `minimal bare and minimal, just the essentials to get you started`

Đặc điểm của `React Native Without Expo` là trong thư mục `project` sẽ có thêm các thư mục `ios` và `android` để build app cho `IOS` và `Android`

Sau khi cài đặt xong tất cả các yêu cầu cần thiết, ta sử dụng lệnh sau để chạy ứng dụng:
- Đối với `Android`:
```bash
npm run android
```
- Đối với `IOS`:
```bash
npm run ios
```

### 4.4. Sử dụng `React Native CLI` để tạo 1 dự án `React Native` mới
Ta sử dụng lệnh sau để tạo 1 dự án `React Native` mới mà không dùng `Expo`:
```bash
npx react-native init <tên-dự-án>
```
Các bước tiếp theo tương tự như ở phần `4.3`

### 4.5. Eject `Expo App` thành `Expo Bare Workflow App`
Để chuyển đổi từ `Expo App` sang `Expo Bare Workflow App`, ta sử dụng lệnh sau:
```bash
npx expo prebuild
```

Sau đó, chúng ta sẽ được hỏi về việc đặt tên cho `Android` và `IOS` package, chúng ta đặt theo tên theo dạng đảo ngược của `domain` của chúng ta, ví dụ: `com.example.myapp` để sau này có thể deploy lên `Google Play Store` hoặc `App Store`

Sau khi chuyển đổi xong, ta sẽ có thêm các thư mục `ios` và `android` trong thư mục `project` để build app cho `IOS` và `Android`

> LƯU Ý: NẾU KHÔNG DÙNG `MACOS`, THÌ SAU KHI EJECT, CHÚNG TA CHỈ THẤY ĐƯỢC DUY NHẤT THƯ MỤC `android` ĐỂ BUILD APP CHO `ANDROID`

## 5. Deploy `React Native` App lên môi trường thật
> LƯU Ý, TRƯỚC KHI DEPLOY APP, CẦN CÀI ĐẶT ĐỦ `NODE_MODULES` VÀ `PREBUILD` CHO APP (NẾU ĐANG DÙNG EXPO HOẶC TRONG THƯ MỤC CỦA PROJECT CHƯA CÓ THƯ MỤC `IOS` VÀ `ANDROID`)

### 5.1. So sánh việc Deploy `React Native` App bằng `Expo` và `Không dùng Expo`
Dùng `Expo` để deploy app lên môi trường thật:
- Việc xây dựng, build các `Binary` cho `IOS` và `Android` được thực hiện bởi dịch vụ `Expo Cloud Service`

> => Việc này giúp cho việc deploy mà không tốn một dung lượng lớn trên máy local, và không cần phải cài đặt các công cụ như `Android Studio`, `XCode`,... Hơn thế nữa, chúng ta có thể deploy app với cả 2 nền tảng `IOS` và `Android` chỉ với 1 máy tính

`Không dùng Expo` để deploy app lên môi trường thật:
- Việc xây dựng, build các `Binary` cho `IOS` và `Android` được thực hiện bởi máy local

> => Việc này tốn nhiều dung lượng trên máy local, và cần phải cài đặt các công cụ như `Android Studio`, `XCode`,... Hơn thế nữa, chúng ta chỉ có thể deploy app cho `IOS` hoặc `Android` mà thôi (Đặc biệt trên `Windows` và `Linux` chỉ có thể deploy app cho `Android`)

### 5.2. Lưu ý khi cấu hình `React Native` App trước khi deploy lên môi trường thật
Trước khi deploy app lên môi trường thật, chúng ta cần phải cấu hình một số `cấu hình` như sau:
- `Permission`: Cấu hình các `quyền` như `Camera`, `Location`,... trong file `AndroidManifest.xml` và `build.gradle` (Đối với `Android`) và `Info.plist` (Đối với `IOS`)
- `App Name & Identifier`: Đặt tên hiển thị cho app, và thêm version cũng như `identifier` cho app để cho app là duy nhất, không trùng với các app khác
- `Splash Screen & Icon`: Thêm `Splash Screen` và `Icon` cho app
- `Environment`: Cấu hình `environment` cho app, lưu trữ các `biến môi trường` như `API_URL`, `API_KEY`, `SECRET_KEY`,...

Chi tiết việc cấu hình cho `React App` cho `Expo` và `Không dùng Expo` tham khảo tại: [Config React Native App](https://docs.expo.dev/versions/latest/config/app/)

#### 5.2.1. Cấu hình tên, phiên bản cho app
**Đối với trường hợp muốn deploy app bằng `Expo`, ta có thể vào file `app.json` để cấu hình các thông số như sau**:
- `name`: Cài đặt trong `expo.name` và `expo.slug`
- `version`: Cài đặt trong `expo.version`, `expo.ios.buildNumber` (Định dạng giống với `expo.version`) và `expo.android.versionCode` (Là số nguyên dương)

> Ví dụ `app.json`:
```json
{
    "expo": {
        "name": "TenUngDung",
        "slug": "TenUngDung",
        "version": "1.0.0"
        },
        "ios": {
            "buildNumber": "1.0.0",
            "supportsTablet": true
        },
        "android": {
            "versionCode": 1,
            "adaptiveIcon": {
                "foregroundImage": "./assets/adaptive-icon.png",
                "backgroundColor": "#FFFFFF"
            }
        }
    }
```

**Đối với trường hợp muốn deploy app mà không dùng `Expo`, ta cần phải cấu hình như sau**:
- `name`:
    + Đối với `Android`: Sửa id `app_name` trong file `strings.xml` trong thư mục `android/app/src/main/res/values/strings.xml`
    + Đối với `IOS`: Sửa trường `Display Name` trong ứng dụng `XCode`
- `version`:
    + Đối với `Android`: Sửa `versionName` và `versionCode` trong file `build.gradle` trong thư mục `android/app/build.gradle`
    + Đối với `IOS`: Sửa trường `Version` trong ứng dụng `XCode`

#### 5.2.2. Cấu hình đọc biến môi trường 
Muốn set `environment` cho app, ta tạo file `.env` trong thư mục `root` của project, sau đó cấu hình như sau:
- Đối với `Expo` thì ta thêm tiền tố `EXPO_PUBLIC_` vào trước tên biến môi trường

Sau đó, để đọc các biến môi trường, ta sử dụng `process.env` như sau:
```javascript
console.log(process.env.EXPO_PUBLIC_API_URL)
```

### 5.2.3. Cấu hình `Splash Screen` và `Icon`
Lưu ý về kích thước của `Splash Screen` và `Icon`:
- `Splash Screen`: Kích thước `1242(w) x 2436(h) px`
- `Icon`: Kích thước `1024(w) x 1024(h) px`. Ngoài ra, cần tạo thêm `adaptive-icon` cho `Android` copy từ `icon` và chỉnh sửa một chút về màu sắc với nền không có màu

Cài đặt `Splash Screen` và `Icon` cho app trong `app.json` như sau:
- Với `Splash Screen`: Cấu hình trong `expo.splash`
- Với `Icon`: Cấu hình trong `expo.icon` và `expo.android.adaptiveIcon` (Chỉ dành cho `Android`)
```json
{
    "expo": {
        "splash": {
            "image": "./assets/splash.png",
            "resizeMode": "contain",
            "backgroundColor": "#ffffff"
        },
        "icon": "./assets/icon.png",
        "ios": {
            "supportsTablet": true
        },
        "android": {
            "adaptiveIcon": {
                "foregroundImage": "./assets/adaptive-icon.png",
                "backgroundColor": "#FFFFFF"
            }
        }
    }
}
```

#### 5.2.3. Cấu hình `Permission` cho app
** Đối với `Expo`, ta không cần phải cấu hình `Permission` vì đã được `Expo` hỗ trợ sẵn, chỉ cần thêm `quyền` vào trong file `app.json` là được**
- `Android`: `permissions` (cho phép cài đặt `quyền` cho app), `blockedPermissions` (cho phép cài đặt `quyền` bị chặn)
- `IOS`: `infoPlist` (cho phép cài đặt `quyền` cho app)
- Ngoài ra, đối với các `module` cài đặt thêm, ta cũng cần phải cấu hình `Permission` cho chúng nếu có yêu cầu, với `expo.plugins.[[<tên module đã cài>.{quyền1, quyền2}]` (đối với `Expo`)

> Ví dụ cấu hình `Permission` cho `Camera` và `Location`: app.json:
```json
{
    "expo": {
        "android": {
            "permissions": [
                "CAMERA",
                "ACCESS_FINE_LOCATION",
                "ACCESS_COARSE_LOCATION"
            ]
        },
        "ios": {
            "infoPlist": {
                "NSCameraUsageDescription": "Camera permission is required for barcode scanning",
                "NSLocationWhenInUseUsageDescription": "Location permission is required for geolocation",
                "NSLocationAlwaysUsageDescription": "Location permission is required for geolocation"
            }
        },
        "plugins": [
            [
                "expo-image-picker",
                {
                        "mediaLibrary": "ALLOW",
                }
            ]
        ]
    }
}
```


**Đối với `React Native` không dùng `Expo`, ta cần phải cấu hình `Permission` trong từng `file` cụ thể của `Android` và `IOS`. Để cấu hình `Permission` cho app, ta cần phải thêm các `quyền` vào trong file `AndroidManifest.xml` và `build.gradle` (Đối với `Android`) và `Info.plist` (Đối với `IOS`)**

Ví dụ cấu hình `Permission` cho `Camera` và `Location`:
- Đối với `Android`:
```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```

- Đối với `IOS`:
```xml
<key>NSCameraUsageDescription</key>
<string>Camera permission is required for barcode scanning</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>Location permission is required for geolocation</string>
<key>NSLocationAlwaysUsageDescription</key>
<string>Location permission is required for geolocation</string>
```

### 5.3. Deploy `React Native` App
#### 5.3.1. Deploy `React Native` App bằng `Expo EAS`
Tham khảo tại: [Deploy React Native App with Expo EAS](https://docs.expo.dev/build/setup/)

1. Đầu tiên chúng ta cần phải có tài khoản `Expo`, đăng ký tại [Expo](https://expo.dev/)
2. Sau đó, chúng ta cần phải cài đặt `EAS CLI`:
```bash
npm install -g eas-cli
```
3. Đăng nhập vào `EAS CLI`:
```bash
eas login
```
4. Thiết lập cấu hình cho app, với các bước đã nêu ở phần `5.2`
5. Tiến hành build app với `EAS` (Lưu ý vào thư mục `root` của project):
```bash
eas build:configure
```
  Sau khi chạy lệnh trên, trong thư mục `root` của project sẽ có thêm file `eas.json`, chúng ta cần phải cấu hình `eas.json`. Chi tiết về cách cấu hình `eas.json` tham khảo tại: [Configure eas.json](https://docs.expo.dev/build/eas-json/)

##### 5.3.1.1. Cấu hình `eas.json` cho `Android`
Để cấu hình `eas.json` cho `Android` chế độ `preview` (sẽ tạo ra file `APK` để tải xuống), tham khảo tại: [Build APKs for Android Emulators and devices](https://docs.expo.dev/build-reference/apk/)

Chúng ta cần phải cấu hình `eas.json` như sau:
> Thêm `android.buildType` vào `build.preview` trong `eas.json`
```json
{
    "build": {
      "preview": {
        "android": {
          "buildType": "apk"
        }
      }
    }
}
```

SAU ĐÓ, CHÚNG TA SỬ DỤNG LỆNH SAU ĐỂ BUILD APP:
```bash
eas build -p android --profile preview
```

LÚC NÀY, CHÚNG TA SẼ NHẬN ĐƯỢC 1 DÒNG CHỮ ĐỂ ĐẶT TÊN CHO GÓI (ID) `APK` ĐÓ: CHÚNG TA SỬ DỤNG QUY TẮC `DOMAIN NGƯỢC` ĐỂ ĐẶT TÊN CHO GÓI `APK`

SAU KHI NHẤN `Y`, CHÚNG TA SẼ NHẬN ĐƯỢC LINK ĐỂ TẢI XUỐNG FILE `APK` ĐÓ.

> Ngoài ra, chúng ta cũng có thể cấu hình `eas.json` cho `Android` để tạo ra file `aab` (Android App Bundle) để deploy lên `Google Play Store`.

##### 5.3.1.2. Cấu hình `eas.json` cho `IOS`
Để cấu hình `eas.json` cho `IOS` chế độ `preview` (sẽ tạo ra file `IPA` để tải xuống), tham khảo tại: [Build for IOS Simulator](https://docs.expo.dev/build-reference/simulators/)

Chúng ta cần phải cấu hình `eas.json` như sau:
> Thêm `ios.simulator` vào `build.preview` trong `eas.json`
```json
{
    "build": {
      "preview": {
        "ios": {
          "simulator": true
        }
      }
    }
}
```

SAU ĐÓ, CHÚNG TA SỬ DỤNG LỆNH SAU ĐỂ BUILD APP:
```bash
eas build -p ios --profile preview
```

LÚC NÀY, CHÚNG TA SẼ NHẬN ĐƯỢC 1 DÒNG CHỮ ĐỂ ĐẶT TÊN CHO GÓI (ID) `IPA` ĐÓ: CHÚNG TA SỬ DỤNG QUY TẮC `DOMAIN NGƯỢC` ĐỂ ĐẶT TÊN CHO GÓI `IPA`

SAU KHI NHẤN `Y`, CHÚNG TA SẼ NHẬN ĐƯỢC LINK ĐỂ TẢI XUỐNG FILE `IPA` ĐÓ.

> Ngoài ra, chúng ta cũng có thể cấu hình `eas.json` cho `IOS` để tạo ra file `app` để deploy lên `App Store`. 

#### 5.3.2. Deploy `React Native` App không dùng `Expo`
1. Tạo khóa `keystore` cho app (Đối với `Android`):

    Đối với `Windows` cần vào `cmd` với quyền `Administrator` ở đường dẫn `C:\Program Files\Java\jdk[x.x.xư\bin`, sau đó chạy lệnh sau:
```bash
keytool -genkeypair -v -storetype PKCS12 -keystore my-upload-key.keystore -alias my-key-alias -keyalg RSA -keysize 2048 -validity 10000
```

2. Nhập `keystore` trong Terminal (Tùy ý với độ dài 6 ký tự) và tiếp tục nhập các phần còn lại.
3. Sau khi tạo xong, chúng ta sẽ có file `my-upload-key.keystore` trong thư mục hiện tại, chúng ta cần phải chuyển file này vào thư mục `android/app` của project.
4. Cấu hình `keystore` trong file `gradle.properties` trong thư mục `android` của project:
```properties
MYAPP_UPLOAD_STORE_FILE=my-upload-key.keystore
MYAPP_UPLOAD_KEY_ALIAS=my-key-alias
MYAPP_UPLOAD_STORE_PASSWORD=<keystore-password đã nhập ở trên>
MYAPP_UPLOAD_KEY_PASSWORD=keystore-password đã nhập ở trên>
```
5. Thêm 1 số đoạn code sau vào file `build.gradle` trong thư mục `android/app` của project:
```gradle
...
...
android {
    ...
    defaultConfig { ... }
    signingConfigs {
        release {
            if (project.hasProperty('MYAPP_UPLOAD_STORE_FILE')) {
                storeFile file(MYAPP_UPLOAD_STORE_FILE)
                storePassword MYAPP_UPLOAD_STORE_PASSWORD
                keyAlias MYAPP_UPLOAD_KEY_ALIAS
                keyPassword MYAPP_UPLOAD_KEY_PASSWORD
            }
        }
    }
    buildTypes {
        release {
            ...
            signingConfig signingConfigs.release
        }
    }
}
...
```
6. Build app với `release` mode:
```bash
cd android
./gradlew bundleRelease
```
    Sau khi build xong, chúng ta sẽ có file `aab` trong thư mục `android/app/build/outputs/bundle/release`, chúng ta có thể deploy file này lên `Google Play Store`
7. Để build app với `debug` mode, chúng ta sử dụng lệnh sau:
```bash
cd android
./gradlew bundleDebug
```
    Sau khi build xong, chúng ta sẽ có file `aab` trong thư mục `android/app/build/outputs/bundle/debug`, chúng ta có thể deploy file này lên thiết bị di động để test
8. Để build app với `apk` mode, chúng ta sử dụng lệnh sau:
```bash
cd android
./gradlew assembleRelease
```
    Sau khi build xong, chúng ta sẽ có file `apk` trong thư mục `android/app/build/outputs/apk/release`, chúng ta có thể deploy file này lên thiết bị di động để test
